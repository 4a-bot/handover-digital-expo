# 設計決策與理由

日期：2026-11-16

## 主題與範圍

我選擇「交接有據」，將場景聚焦在小型成果展中的課程專題與數位作品展。專案希望解決的問題是：工作人員中途接手時，除了知道待辦事項，也能找到正確文件、操作方法及完成判準。

首批展品為清單整理器與展品說明牌產生器。兩者都有實際用途和可重現的輸入、輸出，能讓收件、展示試跑、備援與改版交接具體呈現。

## 首頁與查找方式

我決定採用「展務工作台」，先顯示任務與接手狀態，讓進入網站的人先知道目前要處理什麼，再前往流程、展品、範本或問題處理頁面。文件與任務互相連結，減少在多個資料夾中反覆查找。

## 視覺與名稱

我選擇「深色展場」作為正式視覺，以深色背景與薄荷綠點綴。共用頁面與兩個工具首次開啟時皆採 night 主題，同時保留訪客主動選擇的閱讀偏好。

正式名稱為「交接有據｜數位展務工作台」，強調每項交接都能找到文件、操作與確認依據。GitHub 儲存庫名稱為 `handover-digital-expo`。

## 內容與維護方式

- 任務對展品、範本與問題案例的關聯，以任務資料為主；其他頁面由此產生索引，減少雙向清單同步的負擔。
- 空白範本、填寫示例與網頁欄位共用同一資料來源，修改欄位後重新產生下載檔。
- 除了完成網站，也實際演練新增任務與修改既有表單，確認 AGENTS.md 足以支持後續維護。
- 開發過程與 AI 協作；程式修改、內容核對及測試結果保留於專案文件。

## 後續變更原則

主題、名稱、視覺及主要功能範圍變更前，先比較具體方案並與我確認。一般修正依 AGENTS.md 完成。每項已確定的變更補上理由，同步修改規則與受影響內容；尚未定案的想法明確標記為待討論。
