# 按 AGENTS.md 新增與修改內容的實際演練

日期：2026-11-16。本次與 AI 協作，依 AGENTS.md 擴充網站內容；以下記錄程式與文件的修改及驗證。

## 要解決的缺口

原有流程從現場示範直接走到撤展，缺少中途換班時「交出什麼、接手者如何確認」的具體任務。網站只保存本機資料，因此不能讓接手者誤以為換一台裝置就會同步進度。

## 依規則進行的修改

| 項目 | 修改前 | 修改後 |
|---|---|---|
| 任務 | 12 項 | 13 項，新增 shift-handover |
| 現場執行階段 | 開場試跑、示範作品 | 加入換班交接與接手試跑 |
| 後續節點 | demonstrate-record → close-display | demonstrate-record → shift-handover → close-display |
| F05 表單 | 7 欄 | 8 欄，新增交付材料與接手確認 |
| 比較頁計數 | 固定寫 12 項任務 | 由正式資料計算數量 |

新增任務沿用 id、phaseId、role、前置資料、步驟、產出、完成判準、關聯與後續任務等欄位。首頁、任務詳情、搜尋、範本反向連結及交接匯出沿用共用渲染邏輯；只在發現比較頁數量硬編碼時修正一次共用程式。

修改前快照為 docs/history/tasks-before-extension.json、phases-before-extension.json、templates-before-extension.json；修改後資料位於 dist/data/。AGENTS-v0.4.md 保存修改前規則的整理稿，檔首註明敘述修訂；逐字原稿可由 Git 歷史追溯。資料快照未作文字改寫。

## 規則如何因此改進

AGENTS.md 第 11 節補上精確欄位型別、階段登記、前後任務關係、表單三欄格式、動態數量與驗證入口。之後新增任務時，AI 不需要猜測資料放在哪裡，也不需要重新設計頁面。

## 實際檢查

- 內容檢查通過：6 階段、13 任務、2 展品、5 範本、3 問題案例，所有關聯有效。
- 靜態檢查通過：12 份 HTML 的本機路徑與內嵌語法有效，備援工具無外部 JS/CSS。
- Chrome 打開新增任務，顯示前置資料、4 步操作、3 項完成判準、F04/F05 與展品連結。
- 新任務設為待處理後重新整理，狀態仍保留；驗證後恢復待開始。
- F05 詳情顯示新增的第 8 欄，相關任務反向連結含新增單元。
- 在新欄輸入開發驗證文字並下載，實際讀取 Markdown 確認欄名與輸入完整保留。
- 搜尋「換班」出現 1 筆新任務結果，可進入。
- 實際匯出工作紀錄並讀取，包含新任務與待開始狀態。
- 工作台顯示 00 / 13；現場執行階段為 0 / 3；比較頁三種主題均顯示 13 個任務。

本次只改任務、表單、規則及共用數量顯示，未改兩件工具核心。其先前 8 項邏輯測試仍記錄於 validation.md，沒有把未重跑的測試描述成本次新增證據。
