# 交接有據｜數位展務工作台

作業主題：建立自己的 AGENTS.md 或 CLAUDE.md

> 本作業包含公開網站、完整 GitHub 專案、AGENTS.md，以及實際新增與修改內容的演練紀錄。

## 1. 專案簡介

「交接有據」是一個供課程專題與數位作品展使用的展務工作台。它協助籌備者與中途接手者找到目前任務、操作文件、展示入口、完成條件及尚待處理的問題，減少交接時只能靠口頭解釋的情況。

首頁以任務及接手狀態為主，採深色背景與薄荷綠點綴。內容包含六個階段、十三項任務、五份可填寫及下載的範本、三類問題處理指引，以及清單整理器與展品說明牌產生器兩件實際可操作的示範作品。任務與交接紀錄可保存在瀏覽器並匯出 Markdown，供接手者閱讀。

我選擇數位作品展的交接作為主題，並確定以任務為核心的首頁、深色展場風格及「交接有據」這個名稱。製作過程與 AI 協作，運用 AI 協助規則草擬、內容與程式實作、測試、修訂及文件整理。網站中的辦展情境是設計練習，軟體的實際操作與測試結果另有紀錄。

## 4. AGENTS.md

完整規則位於專案根目錄的 [AGENTS.md](../AGENTS.md)，網站「專案說明與規則」也可下載。現行規則為 1.1 版，共十二節，具體約定網站定位、頁面架構、技術入口、檔案位置、資料格式、視覺、擴充流程、工具行為、更新同步、修改邊界、檢查與部署維護。它可以直接用於持續開發這個網站。

規則與實作的對應如下：

| 規則 | 實際對應 |
|---|---|
| 任務包含步驟、產出與完成判準 | 每項任務詳情共用同一結構 |
| 正式內容集中於共用資料 | dist/data 的五份 JSON |
| 單一來源維護關聯 | 展品及範本的相關任務由 tasks.json 反向產生 |
| 統一色票與元件 | 深色展場的 CSS 變數及共用卡片、表單、按鈕 |
| 更新來源後重建下載文件 | prepare_templates.py 產生空白範本及完整示例 |
| 如實區分示範與驗證 | 範本標示教學情境，實際軟體結果另存 validation.md |

## 5. 規則如何幫助 AI 繼續完成

之後要新增工作單元時，可請 AI 先閱讀 AGENTS.md，再依固定欄位加入 tasks.json，登記所屬階段及前後任務，必要時更新表單。若新增獨立頁面，第 7 節也明確指定路由、頁面產生器、渲染函式、導覽及搜尋索引的修改位置。共用程式會把資料呈現在首頁、流程頁、搜尋、相關文件與匯出結果中。AI 最後必須重建下載檔、檢查資料關聯及實際操作，並記錄修改原因。

本次已真正演練一次：新增「執行換班交接與接手試跑」，使任務由十二項增為十三項；將原本「示範後直接撤展」的流程加入換班節點；F05 表單由七欄增為八欄，補上交付材料與接手確認。演練發現比較頁任務數寫死，修正為動態計算，並回寫規則要求。修改前資料快照與正式資料可直接比對；規則歷史整理稿另附編輯說明，逐字原稿保留於 Git 歷史。

可重複使用的指令範例：

> 請先閱讀 AGENTS.md、專案範圍及決策紀錄。在既有階段新增一項「展示結束後核對下載文件」任務。依固定欄位寫明步驟、產出及完成判準，連到既有 F05 範本；檢查它與其他任務是否重複，更新階段及前後節點，執行相關驗證並記錄修改。沿用現有風格與元件。

這段指令可用於下一次擴充；本次已完成的換班交接演練詳見 [extension-log.md](extension-log.md)。

## 6. 測試與限制

兩件工具先前完成八項邏輯測試；網站已檢查輸入錯誤、下載、任務保存、搜尋、篩選、表單與窄版面。這次擴充另完成新任務狀態保存、F05 新欄位下載、反向連結、搜尋及匯出驗證。十二份 HTML 的本機路徑及內嵌語法檢查通過。

目前沒有多人即時同步與匯入功能；匯出的 Markdown 供接手者閱讀。瀏覽器紀錄不會跨裝置同步。雲端測試環境未能驗證系統列印及本機 file 協定執行，因此沒有聲稱實機列印或離線開啟已通過；不影響公開網站的兩件工具操作。
